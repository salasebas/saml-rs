<div class="saml-label">Readme</div>

<p class="saml-lead">
	Sign a person in with SAML 2.0, or issue that login from your own identity provider. **Signatures and
	encryption go through [bergshamra](https://crates.io/crates/bergshamra)**, so the build does not need
	`libxml2`, `xmlsec1`, or OpenSSL.
</p>

```toml title="Cargo.toml"
[dependencies]
saml-rs = "0.6"
```

The package name is `saml-rs`. Rust imports `saml_rs`. Method signatures live on [docs.rs](https://docs.rs/saml-rs).

<div class="saml-label">Service provider</div>

```rust title="sp.rs"
let sp = Saml::sp(
    SpConfig::builder(EntityId::try_new("https://sp.example.com/metadata")?)
        .acs_endpoint(AcsEndpoint::post("https://sp.example.com/acs")?)
        .credentials(credentials)
        .validation(SpValidationPolicy::recommended())
        .build()?,
)?;

let started = sp.start_sso(&idp, StartSso::redirect())?;
```

Store `started.pending`, send `started.outbound` to the browser, and call `finish_sso` when it posts back. The full flow is in [Service provider](/guides/service-provider-sso/).

<div class="saml-label">Before production</div>

<Aside type="caution" title="Pre-1.0">
	A minor release can change the API. There has been no external security audit. Pin the peer's metadata signing key, and read [XML signatures](/explanation/xml-signature-recommendations/) before production.
</Aside>
