# How to upgrade from 0.6 to 0.7

Use this guide to upgrade `saml-rs`, `opensaml`, `samlify`, or `samlet` from
the latest `0.6.x` release to `0.7.x`. Apply only the sections that affect
your integration. The [changelog](../../CHANGELOG.md) lists compatible additions.

## Replace removed policies and check defaults

Replace `SpValidationPolicy::strict()`, `IdpValidationPolicy::strict()`, and
`LogoutPolicy::strict()` with `recommended()`. Set additional checks explicitly.
For an SP that requires signed assertions, signs AuthnRequests, and requires
an audience restriction:

```rust
let policy = SpValidationPolicy {
	assertions: AssertionSignaturePolicy::RequireSigned,
	authn_requests: AuthnRequestSigningPolicy::Sign,
	audience: AudienceValidationPolicy::Validate,
	..SpValidationPolicy::recommended()
};
```

To require the RSA-SHA2 XML-DSig profile too, set
`xml_signatures: XmlSignatureProfile::StrictRsaSha2`.
For an IdP that rejects unsigned AuthnRequests, set
`IdpValidationPolicy::authn_requests` to `AuthnRequestValidationPolicy::RequireSigned`.
`LogoutPolicy::recommended()` still requires signed requests and responses.

Check code that relies on constructor defaults. Policy `default()` and
`SpConfig` and `IdpConfig` `new`, `try_new`, and `builder` now use Recommended.
It allows unsigned AuthnRequests and bearer assertions without audience
restrictions. It makes AuthnRequest signing and direct Assertion signatures
optional. Use the fields above to require those checks.

To retain the legacy permissive policy, select `compatibility()` explicitly.
Without a crypto provider, select it or another policy that does not require
signatures. Otherwise `try_new` and `builder().build()` return
`SamlError::Unsupported`. `new` does not validate.
Raw settings and individual field defaults are unchanged.
See [validation presets](../adr/0002-validation-presets.md) for policy details.

## Fix compilation errors

### Extend exhaustive matches

Add arms for these new variants where you match the corresponding enum:

| Enum | Add arms for |
| --- | --- |
| `SsoResponseBinding` | `Artifact` |
| `BrowserInput` | `Artifact`, `Soap { envelope, channel, .. }` |
| `LogoutBinding` | `Soap` |
| `saml_rs::constants::Binding`, also exported through `raw` | `Soap` |
| `saml_rs::constants::ParserType` | `ManageNameIdRequest`, `ManageNameIdResponse` |
| `SignatureAlgorithm` | `RsaSha1`, `DsaSha1`, `HmacSha1` |
| `TransformAlgorithm` | `CanonicalXml` |

Use `BrowserInput::<SsoResponse>::artifact` for artifact input, and `soap`
or `soap_with_channel` on logout input types for SOAP. Raw SSO and logout
creation still reject SOAP with `SamlError::UnsupportedBinding`. Typed
AuthnRequest and logout calls return an error for `BrowserInput::Artifact`.

`Binding::from_urn` now returns `Binding::Soap` for
`urn:oasis:names:tc:SAML:2.0:bindings:SOAP` instead of `None`, so an
`AuthnRequest` whose `ProtocolBinding` is that URN fails with
`SamlError::UndefinedBinding` instead of `SamlError::Invalid`.
`Metadata::get_support_bindings` lists `Binding::Soap` when metadata publishes
a SOAP `SingleLogoutService`, and an identity provider that publishes only
that endpoint now writes `SessionIndex` in its assertions.

### Complete struct literals

If you list every field in these structs, add the new fields:

- On `Credentials`, raw `EntitySetting`, and raw `FlowOptions`, add `hmac_secret: None` when you do not use HMAC.
- On typed and raw `IdpMetadataConfig`, add `artifact_resolution_service: Vec::new()` when you do not publish artifact resolution.
- On typed and raw `SpMetadataConfig` and `IdpMetadataConfig`, add `manage_name_id_service: Vec::new()` when you do not publish name identifier management.

Existing metadata constructors supply empty lists. Use
`..Default::default()` where the struct supports it.

### Handle metadata generation errors

Handle the new `Result<String, SamlError>` from
`saml_rs::metadata::generate_sp_metadata` and `generate_idp_metadata`, for
example with `?`. Invalid NameID formats return `SamlError::Invalid`.
`try_generate_idp_metadata`, `Saml::sp`, and `Saml::idp` return the same
error for an invalid configured format.

## Update identifiers and comparisons

Use absolute URIs or `NameIdFormat` constants for every format you send.
Replace empty, blank, relative, or malformed values such as `local-format`
with a value such as `urn:example:name-id-format`. Check `NameId`, config
`name_id_format` lists, and raw `EntitySetting::name_id_format`.
Generation now returns `SamlError::Invalid` for invalid formats, including
when you send a received NameID back through logout or name identifier management.

To leave the format unspecified, use `NameId::new(value, None)` or an empty
format list. A blank list entry is an error. Expect generated assertions,
logout requests, and raw AuthnRequest `NameIDPolicy` to omit `Format`
instead of writing `Format=""`. Treat a session NameID format of `None` as
unspecified instead of expecting `Some(NameIdFormat::Custom(String::new()))`.
Custom callbacks that write their own XML remain responsible for it.

If your IdP issues persistent or transient NameIDs longer than 256 characters,
shorten them to avoid `SamlError::Invalid`. `NameId::generate_persistent`
and `NameId::generate_transient` return 41-character values. Received values
are not subject to this new generation limit.

If you parse generated IDs or session indexes as UUIDs, remove that parsing
and allow at least 41 characters in storage. Generated IDs now contain `_`
followed by 40 lowercase hexadecimal digits. Treat them as opaque strings.
Caller-supplied IDs are unchanged.

Update whole-object comparisons where these fields matter:

- Include the received `Attribute::name_format`, or compare only the attribute name and values. It is no longer always `None`.
- Include the assertion's NameID qualifiers when comparing `SsoSession::name_id()` or `subject()`, or compare only `value()` and `format()`.
- Allow the new `attributeNameFormats` key when comparing or iterating over raw `FlowResult::extract`.
- Account for `identifiers` and `attributes` in `XmlEncryptionPolicy` debug output, including containing configs, and `identifier_encryption` in `StartSlo` debug output.

## Correct metadata and endpoint selection

### Check keys, roles, and signing flags

If metadata contains both SP and IdP roles, publish each role's keys and
logout endpoints inside its own descriptor. `SpMetadata` and `IdpMetadata`
now use only their respective roles, including through typed descriptors
and raw providers. Missing keys or endpoints in that role no longer fall
back to the other role. Generic `Metadata::parse` remains role-independent.
A message signed with a key that only the other role publishes fails, usually
with `SamlError::CertificateMismatch`. Encrypting for a role that publishes no
encryption certificate returns `SamlError::MissingMetadata`, even when the
other role publishes one. A raw `IdentityProvider` writes `SessionIndex` only
when its `IDPSSODescriptor` publishes a `SingleLogoutService`.

Correct each key's `KeyDescriptor` `use`. A signing-only key no longer
encrypts, and an encryption-only key no longer verifies signatures, even
when it is the only key. Omit `use` for a key serving both purposes.
Keys without `use` now participate alongside explicitly scoped keys.
When a peer's only key has the other `use`, its XML signatures fail with
`SamlError::NoTrustedCertificate`, its HTTP-Redirect and HTTP-POST-SimpleSign
signatures with `SamlError::SignatureVerification`, and encryption to it with
`SamlError::MissingMetadata`.

If metadata uses `1`, `0`, or surrounding whitespace for signing flags,
check the intended values. `1` now means true. Sign AuthnRequests when
`AuthnRequestsSigned` requires it, reject unsigned requests when
`WantAuthnRequestsSigned` requires it, and require signed assertions when
`WantAssertionsSigned` requires it. Publish `false` where unintended.
`start_sso` returns `ERR_METADATA_CONFLICT_REQUEST_SIGNED_FLAG` when one side
of the SP and IdP metadata is now true and the other is false.

If you compare generated metadata byte for byte or read children by position,
update the expected schema order:

```text
SP before:  KeyDescriptor, NameIDFormat, SingleLogoutService, AssertionConsumerService
SP after:   KeyDescriptor, SingleLogoutService, NameIDFormat, AssertionConsumerService
IdP before: KeyDescriptor, NameIDFormat, ArtifactResolutionService, SingleSignOnService, SingleLogoutService
IdP after:  KeyDescriptor, ArtifactResolutionService, SingleLogoutService, ManageNameIDService, NameIDFormat, SingleSignOnService
```

Prefer updating comparisons over retaining an old order that schema-validating
peers reject. To keep the old service provider order, pass
`elements_order::ONELOGIN` to `elements_order`. For the old identity provider
order, pass the old list above. See
[metadata rules](../conformance/metadata-and-replay.md).

### Select the actual receiving URL

If you publish several receiving URLs for one binding, set the handler's
externally visible URL before `Saml<Idp>::receive_sso`, `receive_slo`, or `finish_slo`:

```rust
let validation = validation.with_recipient_endpoint(
	EndpointUrl::try_new("https://idp.example.com/sso/second")?,
);
```

Take the URL from trusted handler configuration or HTTP request context.
Use `SingleSignOnService` `Location` for SSO, `SingleLogoutService` `Location`
for logout requests, and `ResponseLocation` for logout responses, falling
back to `Location` when absent. Ambiguous or unpublished receiving URLs
return `SamlError::Invalid`. Messages for another URL return
`SamlError::DestinationMismatch`, even if that URL is also published.

If your IdP uses `AuthnRequestValidationPolicy::RequireSigned`, ensure peers
include `Destination`, set to your `SingleSignOnService` URL, on signed
Redirect, POST, and SimpleSign AuthnRequests.
Missing values now return `SamlError::DestinationMismatch`.
`saml-rs` SPs already send it. PAOS reception is unchanged.

### Check the default ACS and binding

If login relied on the first ACS, mark the intended default with
`AcsEndpoint::mark_default` or update metadata. `respond_sso` without an
explicit ACS or binding, and `initiate_sso`, now use the SP role's default ACS.
Match its binding with `RespondSso::post` or `RespondSso::simple_sign`.
A mismatch or unsupported default returns `SamlError::Invalid`.

Binding-only requests, `start_sso`, and raw lookups choose the default within
the binding's candidates. Explicit ACS URLs and indexes retain their selection.
For PAOS, set `StartPaosSso::acs_url` if the new default selects another endpoint.

## Handle artifact responses and services

If your IdP receives `SsoResponseBinding::Artifact`, answer with
`respond_sso_artifact` and `RespondSso::artifact(...)`. `receive_sso` now
accepts that request, while `respond_sso` returns `SamlError::Invalid`.
Publish a SOAP `ArtifactResolutionService` at the delivery index and answer
`ArtifactResolve` with `answer_artifact_resolve`. Use distinct endpoint indexes.
See [artifact response handling](../conformance/web-browser-sso-artifact.md).

If you detected an artifact ACS through `SamlError::UndefinedBinding`,
compare `AcsEndpoint::binding` with `SsoResponseBinding::Artifact` instead.
`SsoResponseBinding::try_from(Binding::Artifact)` and
`AcsEndpoint::try_from_raw` now succeed. An explicit artifact ACS index now
starts artifact login through `StartSso`, while `respond_sso` returns
`SamlError::Invalid` for it. ECP and request and logout bindings still reject
HTTP-Artifact.

To enable name identifier management, publish the required SOAP or Redirect
endpoint through `manage_name_id_service`. IdPs support both bindings. SPs
support only Redirect. A missing endpoint returns `SamlError::MissingMetadata`.
See [name identifier management](../conformance/name-id-management.md).

## Update logout subjects, templates, and responses

If you customise `TemplatePolicy::logout_request_template`, use the subject's
NameID attributes as placeholders:

```xml
<saml:NameID NameQualifier="{NameQualifier}" SPNameQualifier="{SPNameQualifier}"
	Format="{NameIDFormat}" SPProvidedID="{SPProvidedID}">{NameID}</saml:NameID>
```

An attribute whose complete value is a placeholder is omitted when there is no
value for it. Session participant generation without producer rules sends the
template as written, so add the placeholders there too.

`start_slo` now sends the subject's format and qualifiers rather than the
first local format. A template that disagrees can return
`SamlError::ProtocolProfile`. For SP logout, use `SsoSession::logout_subject`
or supply the session's format and qualifiers yourself.
For IdP logout, pass what the issued assertion carried.

If you set `SPProvidedID` on an issued subject, ensure the SP supplied that
alternative identifier. SSO responses now write it instead of dropping it.
Login response templates cannot represent it and now return `SamlError::Invalid`.
Drop the template or pass `None`. Standard response generation still omits
`NameQualifier` and `SPNameQualifier`. Send those in logout only if a custom
response template wrote them into the assertion.

Accept logout responses at a peer's non-empty `ResponseLocation`, or omit
that attribute to use `Location` for both directions. Under SP generation
rules, use HTTPS or select `RespondSlo::allow_http_single_logout`.
Pass `respond_slo` the descriptor matching the request issuer to avoid
`SamlError::IssuerMismatch`.

If you read SOAP logout `BindingContext`, expect protocol XML in `context`
rather than base64, and an empty `entity_endpoint` on responses.

If you handle refused logout through `SamlError::StatusNotSuccess`, handle
signature, issuer, correlation, and destination errors as failed logout too.
Typed and raw logout now perform their authentication and correlation checks
before reporting non-Success status. Under
`LogoutSignaturePolicy::AllowUnsignedForCompatibility`, an unsigned response
still reports its status after the correlation checks. See
[Single Logout](../conformance/single-logout.md).

## Check encryption and signature settings

If your IdP sets non-default `signed_reference_transforms`, verify the output
of `respond_sso` and `initiate_sso`. They now honour that setting. To retain
the old transforms, select `EnvelopedSignature` and `ExclusiveCanonicalization`.
Artifact responses, PAOS, and SOAP logout still use the default transforms.

If you configure `Credentials::decryption_key`, expect received encrypted
assertions, IDs, and attributes to be decrypted even when you did not select
their generation. Handle decryption failures instead of relying on ignored
attributes or undecrypted identifiers. An `<EncryptedAttribute>` that does not
decrypt, for example one encrypted for another recipient, returns
`SamlError::Crypto`. On RustCrypto, select
`with_insecure_software_rsa_key_transport_decryption_allowed` when needed.
Generation remains opt-in. Selecting encryption still requires the encrypted form.

For requested subjects, handle `RequestedSubjectIdentifier::NameId` after
decryption. A requested `<EncryptedID>` is decrypted only when the request is
signed or its `EncryptedData` uses AES-GCM. An undecrypted `EncryptedId` still needs an error response for
an unrecognised subject. For signed logout requests or requests over an
authenticated SOAP channel, use the decrypted NameID to find sessions.

If your peer sends multiple encrypted assertions, ensure all are intended
for this SP and pass validation. Every one is now decrypted and checked.
Under `AssertionSignaturePolicy::RequireSigned`, each must be signed,
including plaintext assertions beside encrypted ones in a response without
a verified signature. A later invalid or undecryptable assertion rejects
the whole response. There is no option to skip it.
Direct `decrypt_assertion` calls also decrypt every encrypted assertion,
while separately returning the first. Raw flows still read the first bearer assertion.

Require schema-shaped encrypted content from peers: one `EncryptedData`
followed only by `EncryptedKey` elements, decrypting to one Assertion.
Other content now returns `SamlError::ProtocolProfile`. No setting restores
the old behaviour.

If a peer uses RSA-v1.5 key transport, ask it to use RSA-OAEP. Otherwise,
select `with_rsa15_key_transport_decryption_allowed`, enable
`crypto-legacy-algorithms`, and retain the software RSA opt-in on RustCrypto.
Without that selection, any RSA-v1.5 key causes `SamlError::Unsupported`,
including sibling keys beside `EncryptedData`. For raw APIs, set
`allow_rsa15_key_transport_decryption` on `AssertionDecryptionOptions`,
`EntitySetting`, or `FlowOptions`.
See [XML security settings](../conformance/xml-security-algorithms.md).

## Update error handling and encoded input

If you map `SamlError` cases by name, handle these additions:

- Treat `EncryptionRequired { element }` as a rejected response containing plaintext where encryption was required.
- Handle `ArtifactNotReturned` when successful artifact resolution contains no protocol message.
- Handle `SoapChannelProtection` when the attested SOAP channel lacks required protection.

`SamlError` remains `#[non_exhaustive]`, so existing wildcard arms still compile.

If inbound base64 contains Unicode whitespace or vertical tabs, remove it.
`base64_decode_with_limit`, used by Redirect, POST, and SimpleSign reception,
now ignores only space, tab, CR, LF, and form feed. Other non-alphabet bytes
are rejected. `base64_decode` is unchanged.
